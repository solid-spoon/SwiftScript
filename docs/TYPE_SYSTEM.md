# TYPE_SYSTEM.md

Спецификация системы типов SwiftScript. Документ описывает, какие типы существуют, как они проверяются и как стираются. Если код и документ расходятся — это баг.

## Обзор

Типы в SwiftScript существуют **только на этапе компиляции**. Компилятор проверяет совместимость и **стирает** аннотации в выходном JavaScript. Runtime не содержит проверок типов.

**Цель системы типов** — поймать ошибки до запуска и сделать код читаемым.
**Не цель** — доказать корректность программы или обеспечить безопасность в смысле Rust/Swift.

**Область применения:** типы нужны в исходнике, чтобы:
- Читать сигнатуры функций и структуры.
- Ловить ошибки при передаче несовместимых значений.
- Помогать IDE (hover, автодополнение).

**Область применения не включает:**
- Runtime-проверки.
- Типизацию через вывод для сложных случаев.
- Subtyping, наследование, протоколы.

## Встроенные типы

### Примитивы

| Тип | Описание | JavaScript |
|-----|----------|------------|
| `Int` | Целое число | `number` |
| `Float` | Дробное число | `number` |
| `Bool` | Логическое значение | `boolean` |
| `String` | Строка | `string` |
| `Void` | Отсутствие значения | `undefined` |
| `Any` | Любое значение | любой |

`Int` и `Float` **неразличимы в рантайме**. Оба — `number`. Разница только в проверках на этапе компиляции.

> ⚠️ **Внимание:** `1 / 2` в SwiftScript даёт `0.5`, потому что `number` в JS — это `Float64`. Разделения на целочисленное и дробное **нет**.

### Опциональные типы

`T?` — опциональное значение типа `T`. В JS — `T | null | undefined`.

```swift
let x: Int? = nil
let y: Int? = 5
let z: Int = 5      // z не совместим с x или y без развёртки
```

**Правила:**

- `T` совместим с `T?` **неявно**.
- `T?` **не** совместим с `T` без развёртки.
- `T?` совместим с `U?`, если `T` совместим с `U`.

**Развёртка:**

| Синтаксис | Поведение |
|-----------|-----------|
| `x!` | Развёртка с ошибкой при `nil` |
| `x ?? default` | Развёртка с fallback |
| `if let y = x { ... }` | Развёртка в блоке |
| `guard let y = x else { ... }` | Развёртка в оставшейся части области |
| `x?.field` | Опциональная цепочка |

### Коллекции

| Тип | Описание | JavaScript |
|-----|----------|------------|
| `[T]` | Массив элементов `T` | `Array` |
| `[K: V]` | Словарь с ключами `K` и значениями `V` | `object` |

> ⚠️ **Внимание:** словарь в SwiftScript генерируется как **объект JavaScript**, а не как `Map`. Ключи приводятся к строкам через `String(key)`. Это ограничение v1.

`Set<T>` **не входит** в v1.

### Кортежи

`(A, B, ...)` — кортеж из значений указанных типов. В JS — массив.

```swift
let pair: (Int, String) = (1, "one")
let (a, b) = pair
```

> ⚠️ **Внимание:** в JS это массив, а не tuple. Доступны методы массива (`.length`, `.map`, `.push`). Это не проверяется.

### Функции

`(A, B) -> C` — функция, принимающая `A` и `B`, возвращающая `C`.

```swift
let f: (Int, Int) -> Int = { $0 + $1 }
```

Совместимость функций **ковариантна по возврату и контравариантна по аргументам**:

```
(A) -> B совместим с (C) -> D
если C совместим с A, и B совместим с D
```

Это правило в v1 **не проверяется**. Функции считаются совместимыми, если совпадают **по структуре**.

## Пользовательские типы

`struct` и `enum` вводят именованные типы в области видимости.

```swift
struct Point { let x: Int; let y: Int }
enum Status { case ok; case error(String) }
```

`Point` и `Status` — **номинальные** типы. Два разных `struct Point` из разных файлов — разные типы, даже если поля совпадают.

> ℹ️ **Примечание:** номинальность не реализована. Сейчас `Point` — это просто имя, привязанное к структуре. Если два модуля экспортируют `Point`, будет конфликт имён.

### Структуры

Тип структуры — это её **имя**. Поля и методы не влияют на совместимость.

```swift
struct Point { let x: Int; let y: Int }
struct Pair { let a: Int; let b: Int }

let p: Point = Point(x: 1, y: 2)
let q: Pair = p          // ошибка: разные типы
```

> ❓ **Требуется уточнение:** реализована ли номинальность в checker'е, или совместимость по структуре. Текущее поведение не определено — checker не написан.

### Перечисления

Тип перечисления — это **имя** enum'а. Случаи не создают отдельных типов.

```swift
enum Status { case ok; case warn(String) }

let s: Status = .ok
let t: Status = .warn("slow")
```

Payload внутри случая имеет **свой тип**, но он не виден снаружи.

## Правила совместимости

Значение типа `A` совместимо с типом `B`, если выполняется хотя бы одно:

| Правило | Условие |
|---------|---------|
| **Идентичность** | `A === B` |
| **Числа** | `A === Int`, `B === Float` или наоборот |
| **Опциональная упаковка** | `A === T`, `B === T?` для любого `T` |
| **Опциональная развёртка** | `A === T?`, `B === T`, **только в контексте развёртки** |
| **Коллекции** | `A === [T]`, `B === [U]`, `T` совместим с `U` |
| **Кортежи** | `A === (T1, T2)`, `B === (U1, U2)`, каждый `Ti` совместим с `Ui` |
| **Any** | `B === Any` |
| **Функции** | `A === (A1) -> A2`, `B === (B1) -> B2`, аргументы и возврат совместимы |

**Не совместимы:**

- `Int` и `String`.
- `Bool` и `Int`.
- `T` и `U` для разных пользовательских типов.
- `T?` и `U` без развёртки.

> ⚠️ **Внимание:** неявная совместимость `Int` → `Float` — **в одну сторону**. `Float` не совместим с `Int`.

### Совместимость для присваивания

Для `let x: T = value`:

1. Тип `value` должен быть совместим с `T`.
2. Если `value` имеет тип `U?` и `T === U`, требуется развёртка.

### Совместимость для вызова функции

Для `f(a, b)`:

1. `f` должен иметь тип функции с двумя параметрами.
2. Тип `a` совместим с типом первого параметра.
3. Тип `b` совместим с типом второго параметра.
4. Результат — возвращаемый тип `f`.

### Совместимость для return

Для `return expr` в функции с возвратом `T`:

1. Тип `expr` совместим с `T`.
2. Если функция возвращает `Void`, `expr` должен отсутствовать или иметь тип `Void`.

## Вывод типов

Компилятор выводит типы в **ограниченных** позициях. Не полный Hindley-Milner.

### Где выводится

**Литералы:**
```swift
let x = 42           // Int
let y = 3.14         // Float
let z = "hello"      // String
let b = true         // Bool
let n = nil          // ошибка: тип не выводится
```

**Коллекции:**
```swift
let a = [1, 2, 3]        // [Int]
let b = ["a", "b"]       // [String]
let c = ["k": 1]         // [String: Int]
let d = []               // ошибка: тип не выводится
let e: [Int] = []        // OK
```

**Кортежи:**
```swift
let t = (1, "hello")     // (Int, String)
```

**Вызовы функций:**
```swift
let p = Point(x: 3, y: 4)    // Point
let r = fib(10)              // Int
let s = "Hello, \(name)"     // String
```

**Замыкания:**
```swift
let f = { $0 * 2 }              // ошибка: тип не выводится
let g: (Int) -> Int = { $0 * 2 }    // OK: тип из аннотации
let h = nums.map { $0 * 2 }     // [Int] → [Int], если nums: [Int]
```

> ⚠️ **Внимание:** замыкания без контекста **не выводятся**. Нужна явная аннотация или контекст вызова.

**Enum-случаи:**
```swift
let s: Status = .ok          // OK: тип из аннотации
let s = Status.warn("slow")  // OK: тип из квалификатора
let s = .warn("slow")        // ошибка: контекст неизвестен
```

### Где не выводится

- Лямбды без аннотации и без контекста.
- Пустые массивы без аннотации.
- `nil` без аннотации.
- Условные выражения, где ветки имеют разные типы.
- Результаты бинарных операций с разнородными операндами.

### Правила для `let`

```swift
let x = expr
```

1. Вывести тип `expr` → `T`.
2. Если вывод невозможен — ошибка E1006.
3. Ввести `x: T` в область видимости.

```swift
let x: T = expr
```

1. Проверить тип `expr` → `U`.
2. Проверить `U` совместим с `T`.
3. Ввести `x: T`.

### Правила для `var`

Те же, что для `let`. Разница только в изменяемости.

### Правила для присваивания

```swift
x = expr
```

1. Тип `x` должен быть известен → `T`.
2. Тип `expr` совместим с `T`.
3. `x` не должен быть `let`-переменной. Иначе — E1010.

## Проверка выражений

### Бинарные операторы

| Оператор | Левый | Правый | Результат | Примечание |
|----------|-------|--------|-----------|------------|
| `+` | `Int` | `Int` | `Int` | |
| `+` | `Float` | `Float` | `Float` | |
| `+` | `Int` | `Float` | `Float` | Коэрция |
| `+` | `Float` | `Int` | `Float` | Коэрция |
| `+` | `String` | `String` | `String` | Конкатенация |
| `-`, `*`, `/` | `Int` | `Int` | `Int` | |
| `-`, `*`, `/` | `Float` | `Float` | `Float` | |
| `%` | `Int` | `Int` | `Int` | Только целые |
| `==`, `!=` | `T` | `T` | `Bool` | Для одинаковых `T` |
| `<`, `>`, `<=`, `>=` | `Int` или `Float` | то же | `Bool` | |
| `&&`, `\|\|` | `Bool` | `Bool` | `Bool` | |
| `??` | `T?` | `T` | `T` | |
| `..<`, `...` | `Int` | `Int` | `Range<Int>` | |

Смешанная арифметика (`Int` и `Float`) — коэрция в `Float`.

> ❓ **Требуется уточнение:** является ли `Int + Float` ошибкой или коэрцией. В Swift — ошибка. В SwiftScript допустимо, но правило не зафиксировано.

### Унарные операторы

| Оператор | Операнд | Результат |
|----------|---------|-----------|
| `-` | `Int` или `Float` | тот же тип |
| `+` | `Int` или `Float` | тот же тип |
| `!` | `Bool` | `Bool` |

### Тернарный оператор

```swift
c ? a : b
```

1. `c` — `Bool`.
2. Тип `a` совместим с типом `b`, или один из них совместим с другим.
3. Результат — общий тип `a` и `b`.

Если `a` и `b` несовместимы — ошибка E1001.

### Индексация

```swift
arr[i]
dict[k]
```

| Тип `arr` | Тип `i` | Результат |
|-----------|---------|-----------|
| `[T]` | `Int` | `T` |
| `[K: V]` | `K` | `V?` |

> ℹ️ **Примечание:** индексация словаря возвращает **опциональное** значение, потому что ключ может отсутствовать. Это решение требует явной развёртки.

### Доступ к полю

```swift
obj.field
```

1. `obj` — struct, enum, или встроенный тип.
2. `field` — имя поля или метода.
3. Для опционального `obj?.field` — результат опциональный.

### Вызов

```swift
f(args)
```

1. `f` — функция типа `(T1, T2) -> R`.
2. Число аргументов совпадает.
3. Каждый аргумент совместим с параметром.
4. Результат — `R`.

Для конструктора struct:

```swift
Point(x: 1, y: 2)
```

1. Все аргументы именованные.
2. Имена совпадают с именами полей.
3. Типы совместимы.

### Строковая интерполяция

```swift
"Hello, \(expr)"
```

Любой `expr` совместим, потому что `String(...)` принимает `Any`.

## Проверка statements

### `if`

```swift
if cond { ... } else { ... }
```

1. `cond` — `Bool`.
2. Ветки проверяются в новых областях видимости.
3. Если `if` как выражение — обе ветки должны возвращать один тип.

### `while`

```swift
while cond { ... }
```

1. `cond` — `Bool`.
2. Тело — новая область видимости.

### `for`

```swift
for x in src { ... }
```

1. `src` — `[T]`, `String`, или `Range<Int>`.
2. `x` — `T`, `String` (один символ), или `Int`.
3. Тело — новая область видимости с `x`.

> ❓ **Требуется уточнение:** допустим ли `for x in "hello"`. Если да, что такое `x` — символ или строка.

### `return`

```swift
return expr
```

1. Тип `expr` совместим с возвращаемым типом функции.
2. Если функция возвращает `Void`, `expr` должен отсутствовать.

### `switch`

```swift
switch subject {
case pattern: ...
default: ...
}
```

1. `subject` — тип `T`.
2. Каждый паттерн совместим с `T`.
3. Для `PatEnum` — `T` должен быть enum'ом с этим случаем.
4. Для `PatRange` — `T` должен быть `Int`.
5. Для `PatLit` — тип литерала совместим с `T`.
6. Для `PatBind` — `T` любой, вводится новое имя.
7. `default` опционален.
8. Исчерпывающесть **не проверяется**.

### `break` / `continue`

Допустимы только внутри `for` или `while`. Вне цикла — ошибка.

> ❓ **Требуется уточнение:** сейчас в кодогенераторе `break` внутри `switch` превращается в `break _swN`. Если `switch` не внутри цикла, `break` работает как выход из `switch`. Нужно ли запрещать `break` вне цикла и `switch` одновременно.

## Проверка объявлений

### Функции

```swift
func f(a: Int, b: String) -> Bool { ... }
```

1. Имена параметров уникальны в сигнатуре.
2. Типы параметров известны.
3. Возвращаемый тип известен или выводится.
4. Тело проверяется в области видимости с параметрами.
5. Если есть `return expr`, тип `expr` совместим с возвращаемым.
6. Если возврат ненулевой, тело должно завершаться `return` (не проверяется в v1).

### Структуры

```swift
struct Point {
    let x: Int
    let y: Int
    func manhattan() -> Int { ... }
}
```

1. Имена полей уникальны.
2. Имена методов уникальны.
3. Методы проверяются с `self` типа `Point`.
4. Внутри методов `self.x` и `x` означают одно и то же.

### Перечисления

```swift
enum Status {
    case ok
    case warn(String)
}
```

1. Имена случаев уникальны.
2. Каждый случай — константа или функция.

### Импорты

```swift
import { VFS, Window } from "./kernel.sws"
```

1. Модуль существует.
2. Экспортирует указанные имена.
3. Импортированные имена вводятся в область видимости.

> ❓ **Требуется уточнение:** циклы импортов, реэкспорт, относительные пути — не специфицировано.

## Область видимости

### Порядок разрешения имён

Для имени `x`:

1. Локальные переменные в текущем блоке.
2. Параметры текущей функции.
3. Поля структуры, если внутри метода.
4. Локальные переменные во внешних блоках.
5. Top-level объявления файла.
6. Импортированные имена.
7. Встроенные имена (runtime).

Первое совпадение выигрывает. Никакого «все объявления видны до их позиции» — используется **лексический порядок**.

### Hoisting

Функции **видны до объявления** внутри файла. Это значит, что рекурсивные вызовы и взаимные ссылки работают.

```swift
func a() { return b() }
func b() { return 1 }
```

Переменные **не видны до объявления**.

```swift
print(x)    // ошибка: x не объявлен
let x = 5
```

### Shadowing

Разрешено. Локальное объявление перекрывает внешнее в своей области.

```swift
let x = 5
{
    let x = 10      // новое x, перекрывает внешнее
    print(x)        // 10
}
print(x)            // 5
```

> ⚠️ **Внимание:** shadowing может привести к неожиданному поведению. В v1 не диагностируется.

### Области видимости

Новая область создаётся:

- Тело функции.
- Тело метода.
- Тело `if`, `else`, `while`, `for`.
- Тело `switch`-случая.
- Тело замыкания.
- Явный блок `{ ... }`.

## Стирание типов

Кодогенератор **не использует** типы. Все аннотации удаляются:

| SwiftScript | JavaScript |
|-------------|------------|
| `let x: Int = 5` | `const x = 5;` |
| `func f(a: Int) -> Int` | `function f(a)` |
| `struct Point { let x: Int }` | `function Point(_args)` |
| `let p: Point = Point(...)` | `const p = Point(...);` |

В выходном коде **нет следов типов**. Это значит:

- Нельзя проверить тип значения в рантайме.
- Нельзя сделать `typeof x === "Int"`.
- Нельзя различить `Int` и `Float`.

## Что не проверяется

- **Инициализация полей struct'а.** `Point(x: 1)` без `y` не ошибка на этапе проверки. Генерируется объект без поля `y`.
- **Исчерпывающесть `switch`.** `switch s { case .ok: ... }` для трёхвариантного enum'а не ошибка.
- **Завершаемость функций.** `func f() -> Int { }` без `return` не ошибка.
- **Неиспользуемые переменные.** `let x = 5` без использования — не ошибка.
- **Недостижимый код.** Код после `return` — не ошибка.
- **Модификация `let`-поля.** `p.x = 5` для `let x` — не ошибка на этапе проверки, но `Object.freeze` выбросит ошибку в рантайме.
- **Деление на ноль.** Не проверяется.
- **Выход за границы массива.** Не проверяется.
- **Циклические ссылки.** Не проверяются.

## Открытые вопросы

❓ **Смешанная арифметика.** `1 + 2.5` — ошибка или коэрция? В Swift — ошибка. В SwiftScript — не зафиксировано.

❓ **Номинальность структур.** Два `struct Point` с одинаковыми полями — один тип или разные? В Swift — разные. В SwiftScript — не определено.

❓ **Исчерпывающесть `switch`.** Требовать `default` для неполных `switch` — не требовать — предупреждение? Сейчас не проверяется.

❓ **Вывод типа замыканий.** `nums.map { $0 * 2 }` — тип `nums` известен, но как именно checker пробрасывает тип в замыкание? Через аннотацию сигнатуры `map` или через специальный механизм?

❓ **Циклы импортов.** `a.sws` импортирует `b.sws`, `b.sws` импортирует `a.sws` — что происходит? Ошибка, отложенная проверка, разрыв цикла?

❓ **`for x in "string"`.** Допустимо? Если да, что такое `x` — `String` или специальный `Char`?

❓ **`if` как выражение.** Если `if` возвращает значение, как это выражается в типах? `T` или `Void` в зависимости от наличия `else`?

❓ **`switch` как выражение.** Аналогично. Если ветки возвращают `Int`, а `default` отсутствует — что за тип?

❓ **Совместимость функций.** `(Int) -> Int` совместим с `(Int) -> Float`? С `(Float) -> Int`? Правило ковариантности/контравариантности не зафиксировано.

❓ **Отсутствие `Set<T>`.** В core-v2 используется `Set<portId>`. В SwiftScript его нет. Добавлять или обходиться через `[T]` и объекты?
