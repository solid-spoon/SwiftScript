# STDLIB_SPEC.md

Спецификация встроенных функций и типов SwiftScript. Документ описывает, что доступно пользователю «из коробки». Если код и документ расходятся — это баг.

## Обзор

Стандартная библиотека — это **набор имён**, доступных в любой программе без импорта. Не модуль, не отдельный файл. Часть языка.

**Граница с рантаймом:** рантайм ([RUNTIME_SPEC.md](RUNTIME_SPEC.md)) описывает **внутренние** функции, которые кодогенератор вызывает (`_force`, `_range`). Стандартная библиотека описывает **пользовательские** функции, которые доступны в исходнике (`print`, `abs`, `round`).

В v1 stdlib и runtime — **одно и то же**. Разделение появится, когда stdlib станет отдельным модулем.

## Встроенные функции

### Вывод

#### `print(...args)`

Печатает значения через `console.log`.

```swift
print("hello")
print(1, 2, 3)
print()
```

Принимает любое число аргументов, любой тип.

**Возвращает:** `Void`.

### Преобразования

#### `String(x)`

Преобразует в строку с обработкой `null` и коллекций.

```swift
String(42)          // "42"
String(3.14)        // "3.14"
String(true)        // "true"
String(nil)         // "nil"
String([1, 2, 3])   // "[1, 2, 3]"
```

См. [RUNTIME_SPEC.md](RUNTIME_SPEC.md) для полной таблицы.

**Возвращает:** `String`.

#### `Int(x)`

Парсит в целое.

```swift
Int("42")       // 42
Int("42abc")    // 42
Int("abc")      // nil
Int(3.14)       // 3
```

**Возвращает:** `Int?`.

#### `Double(x)`

Парсит в дробное.

```swift
Double("3.14")     // 3.14
Double("abc")      // nil
Double(42)         // 42
```

**Возвращает:** `Float?`.

#### `Bool(x)`

Приводит к булеву через `Boolean`.

```swift
Bool(1)          // true
Bool(0)          // false
Bool("")         // false
Bool("false")    // true
```

**Возвращает:** `Bool`.

> ⚠️ **Внимание:** `Bool("false")` — `true`. Для парсинга строки используйте явное сравнение.

### Математика

#### `abs(x)`

Модуль числа.

```swift
abs(-5)      // 5
abs(3.14)    // 3.14
```

**Возвращает:** тот же тип, что у аргумента.

#### `min(...args)`

Минимум из аргументов.

```swift
min(3, 1, 2)         // 1
min([3, 1, 2])       // NaN (массив — не число)
```

**Возвращает:** число.

> ⚠️ **Внимание:** `min` не работает с массивами. Для массива используйте цикл или `reduce`.

#### `max(...args)`

Максимум из аргументов.

```swift
max(3, 1, 2)         // 3
```

**Возвращает:** число.

#### `round(x)`

Округляет к ближайшему целому.

```swift
round(3.4)      // 3
round(3.5)      // 4
round(-3.5)     // -3
```

**Возвращает:** `Int`.

#### `floor(x)`

Округляет вниз.

```swift
floor(3.9)      // 3
floor(-3.1)     // -4
```

**Возвращает:** `Int`.

#### `ceil(x)`

Округляет вверх.

```swift
ceil(3.1)       // 4
ceil(-3.9)      // -3
```

**Возвращает:** `Int`.

### Функции высшего порядка

В v1 **отсутствуют**. `map`, `filter`, `reduce`, `forEach` — не встроены. Пользователь пишет их сам или использует методы массивов JavaScript напрямую.

```swift
let nums = [1, 2, 3]
let doubled = nums.map { $0 * 2 }    // работает, потому что Array.prototype.map
```

> ℹ️ **Примечание:** методы массива (`map`, `filter`, `reduce`) доступны через прототип JS. Это не часть stdlib SwiftScript, но работает. В будущем, если появится свой `Array`-тип, эти методы переопределятся.

### Работа со строками

В v1 **отсутствует**. Нет `split`, `join`, `replace`, `trim`. Пользователь использует методы String JavaScript напрямую.

```swift
let parts = "a,b,c".split(",")       // работает через String.prototype.split
let joined = ["a", "b"].join("-")    // работает через Array.prototype.join
```

## Встроенные типы

### `Int`, `Float`, `Bool`, `String`

См. [TYPE_SYSTEM.md](TYPE_SYSTEM.md).

### `[T]`

Массив. В JS — нативный `Array`.

Методы (доступны через прототип):

| Метод | Сигнатура | Описание |
|-------|-----------|----------|
| `map` | `(T) -> U` → `[U]` | Преобразование |
| `filter` | `(T) -> Bool` → `[T]` | Отбор |
| `reduce` | `(U, T) -> U`, `U` → `U` | Свёртка |
| `forEach` | `(T) -> Void` → `Void` | Обход |
| `find` | `(T) -> Bool` → `T?` | Первый подходящий |
| `some` | `(T) -> Bool` → `Bool` | Есть подходящий |
| `every` | `(T) -> Bool` → `Bool` | Все подходят |
| `includes` | `T` → `Bool` | Содержит |
| `indexOf` | `T` → `Int` | Индекс или -1 |
| `slice` | `Int, Int` → `[T]` | Срез |
| `concat` | `[T]` → `[T]` | Объединение |
| `reverse` | — → `[T]` | Обратный порядок |
| `sort` | `(T, T) -> Int` → `[T]` | Сортировка |
| `join` | `String` → `String` | Склейка в строку |
| `push` | `T` → `Int` | Добавить в конец |
| `pop` | — → `T?` | Убрать с конца |
| `shift` | — → `T?` | Убрать с начала |
| `unshift` | `T` → `Int` | Добавить в начало |

> ⚠️ **Внимание:** методы `push`, `pop`, `shift`, `unshift`, `sort`, `reverse` **мутируют** массив. В Swift-семантике это невозможно для `let`. В SwiftScript — возможное поведение, не диагностируется.

> ❓ **Требуется уточнение:** стоит ли делать методы массива иммутабельными. Если да, `push` должен возвращать новый массив, а не мутировать.

### `[K: V]`

Словарь. В JS — объект.

Методы: **отсутствуют**. Используйте `Object.keys`, `Object.values`, `Object.entries` напрямую.

```swift
let m = ["a": 1, "b": 2]
let keys = Object.keys(m)        // ["a", "b"]
```

> ⚠️ **Внимание:** `Object.*` — это JavaScript, не SwiftScript. Работает, но не является частью языка.

### `(A, B)`

Кортеж. В JS — массив.

Методы: **доступны как у массива**. Это нежелательно, но неизбежно.

### `T?`

Опциональное. В JS — `T | null | undefined`.

Методы: **отсутствуют**. Только операторы (`??`, `!`, `?.`, `if let`, `guard let`).

## Работа с числами

### Диапазоны

Диапазоны `a..<b` и `a...b` создают **массив** чисел. Это не ленивая последовательность.

```swift
let r = 0..<5           // [0, 1, 2, 3, 4]
let r2 = 0...5          // [0, 1, 2, 3, 4, 5]
```

**Тип:** `[Int]`.

> ⚠️ **Внимание:** `0..<1000000` создаст массив из миллиона элементов. Для больших диапазонов это неэффективно.

### Арифметика

Все стандартные операторы: `+`, `-`, `*`, `/`, `%`. Работают для `Int` и `Float`. Смешанные операнды дают `Float`.

### Деление на ноль

```swift
1 / 0       // Infinity
0 / 0       // NaN
```

В JS деление на ноль не бросает. В SwiftScript — тоже. Проверка не делается.

## Работа со строками

### Интерполяция

```swift
let name = "World"
let greeting = "Hello, \(name)!"
```

Любое выражение внутри `\(...)` преобразуется через `String(...)`.

### Конкатенация

```swift
"Hello, " + "World"
```

`+` для строк работает как конкатенация.

### Сравнение

```swift
"abc" == "abc"       // true
"abc" < "abd"        // true
```

Сравнение лексикографическое, посимвольное.

### Длина

В v1 **отсутствует** встроенная функция. Используйте `x.length`:

```swift
let n = "hello".length       // 5
```

> ❓ **Требуется уточнение:** стоит ли добавить `len(x)` в stdlib. В Swift — `x.count`. В JS — `x.length`.

## Что доступно из JavaScript

Пользователь **может** обращаться к глобальным объектам JavaScript:

- `console`
- `Math`
- `JSON`
- `Object`, `Array`, `String`, `Number`
- `Promise`
- `setTimeout`, `setInterval`
- `document`, `window` (в браузере)
- `process`, `require`, `module` (в Node.js)

Это **не часть SwiftScript**. Это деталь реализации, которая может измениться, если SwiftScript будет компилироваться во что-то другое.

> ⚠️ **Внимание:** использование `console.log` вместо `print` работает, но зависит от окружения. `console` может отсутствовать в не-браузерных и не-Node окружениях.

## Что не входит в stdlib

- **HTTP-клиент.** Нет `fetch`, нет `http.get`.
- **Файловая система.** Нет `readFile`, `writeFile`.
- **Работа с DOM.** Нет `document.querySelector`.
- **Работа со временем.** Нет `now`, `Date` (кроме JS `Date`).
- **Криптография.** Нет `hash`, `random` (кроме `Math.random`).
- **Парсинг JSON.** Нет `parse`, `stringify` (кроме JS `JSON`).
- **Регулярные выражения.** Нет поддержки синтаксиса `/pattern/`.
- **Обработка ошибок.** Нет `try`/`catch` в смысле Swift.

Всё это либо доступно через JavaScript-глобалы, либо не реализовано.

## Планы

В будущих версиях stdlib может расшириться:

| Модуль | Содержимое |
|--------|------------|
| `math` | `sin`, `cos`, `sqrt`, `pow`, `log` |
| `string` | `split`, `join`, `replace`, `trim`, `upper`, `lower` |
| `array` | `sum`, `avg`, `unique`, `chunk` |
| `json` | `parse`, `stringify` |
| `io` | `readFile`, `writeFile` |
| `time` | `now`, `format` |

Каждый модуль — опциональный, через `import`. В v1 — отсутствуют.

> ❓ **Требуется уточнение:** какие модули приоритетны. Судя по прошлым проектам, для core-v2 нужны: `math`, `string`, `json`.

## Совместимость

Имена stdlib **не переопределяются** пользователем. Если пользователь объявит `let print = 5`, компилятор выдаст ошибку или перекроет. Поведение не специфицировано.

**Зарезервированные имена** (не должны использоваться):

```
print  String  Int  Double  Bool
abs  min  max  round  floor  ceil
```

> ⚠️ **Внимание:** список не проверяется. Использование этих имён в пользовательском коде даёт shadowing или переопределение. Может привести к трудноуловимым багам.

## Открытые вопросы

❓ **Граница runtime и stdlib.** В v1 они совпадают. Когда их разделить. Нужен ли `_force` в пользовательском API, или это только внутренняя функция.

❓ **Функции высшего порядка.** Стоит ли добавить `map`, `filter`, `reduce` как часть stdlib, или полагаться на методы массива JS.

❓ **Строковые функции.** Стоит ли добавить `len(x)`, `split(s, sep)`, `join(arr, sep)`, или полагаться на `x.length`, `x.split`, `arr.join`.

❓ **`len(x)`.** В Swift — `x.count`. В JS — `x.length`. Что использовать в SwiftScript.

❓ **Модули stdlib.** `math`, `string`, `json`, `io`. Какие приоритетны. Как импортируются (`import math`? `import { sin } from "std/math"`?).

❓ **`Map` и `Set`.** В core-v2 используются. В SwiftScript нет. Добавить ли `Set<T>` и `Map<K, V>` как встроенные типы.

❓ **Мутирующие методы массива.** `push`, `pop`, `sort` мутируют. В Swift-семантике это недопустимо. Стоит ли делать иммутабельные версии.

❓ **Регулярные выражения.** Поддержка синтаксиса `/pattern/` или только через `new RegExp("...")`.

❓ **Обработка ошибок.** `Result<T, E>` как встроенный тип или пользовательский. `try`/`catch` в Swift-стиле или через `Result`.

❓ **Числовые типы.** `Int` — это `number` в JS. `Float` — тоже `number`. Стоит ли добавлять `Int32`, `Int64`, `Float32`, `Float64` как отдельные типы для читаемости, или одного `Int`/`Float` достаточно.

❓ **`Void`.** Как тип возврата и как значение. `let x: Void = print("hi")` — работает? Стоит ли добавить константу `void` для явности.
